# プログレスマップ（Progress Map）

**今どこに何があるか。なぜ変わったか。**

毎日 AI と話しながらソフトを作る人のための、ファイルとコードの地図です。
すべてのファイルの「今」と、**変更ごとに理由と戻し方（逆向きの差分）を持つ台帳**を持ち、その変更が生まれた会話の節に結びます。git は使いません。

---

## 困っていたこと

AI がコードの大半を書くようになると、三つのものが抜け落ちます。

| 抜け落ちるもの | 何が起きるか |
|---|---|
| **どこにあるか** | 新しい会話がファイル名で探して違うファイルに着き、昨日その設計を決めた会話を見落とす。 |
| **何が消えたか** | ある編集でスタイルシートが88行消え、別の所で行が増えた。ファイル全体では47行減っただけなので、誰も気づかない。 |
| **なぜ変えたか** | git は「何が」変わったかは残す。でも会話で作る開発では「なぜ」は会話の中にあり、git には届かない。後から書くコミットの説明は薄い。 |

## 仕組み

1. **地図** — 読み取り手がフォルダを歩き、物（ファイル）1つにつき1行を作ります。何のための物か（先頭のコメント1行）、大きさ、指紋、つながり（読み込む・リンクする・定義する・使う・取り込む・参照する）。読み取り手はコード用（html・js・css・py・ps1・md・json など）と、オフィス文書用（zip の目録だけ読む）の2種類です。列の名前は話題に依らない汎用だけにし、話題に固有の語はキーと値で持つので、同じ表がどの開発にも使えます。
2. **直した直後に check** — ファイルを直したらすぐ `check(path, reason)` を撃ちます。持っている写しと比べ、**消えた行そのもの**を数え（全体の増減ではなく）、台帳に1行積みます。中身は札（`chg:<セッション>-0007` の形）、理由、そして「今」を「前」に戻す**逆向きの差分**です。大きく消えたら ALERT を出して作業を止めます。
3. **札から会話へ** — 札は道具の戻り値に入るので、会話の記録にそのまま残ります。後で地図を開くと、記録の中から札を探し、いちばん近い結晶の節に結びます。結び付きは表に持たず、見る時に計算します。
4. **戻る** — 「今」は丸ごと持ちます。戻る時は逆向きの差分を新しい順に当て、一段ごとに指紋で検算します。月に一度、丸ごとの写しを撮っておき、鎖が切れた時の足場にします。戻した姿はまず組み立てるだけで、書き込むのは人が了解した後です。

会話の記憶と同じ DuckDB の1ファイルに入っているので、1本の問い合わせで「ファイル → 変更 → 理由 → 会話の節 → 元の行」までたどれます。

## なぜ git を使わないか

git はチームには最良の道具です。でも一人と AI の開発では、手間のかかる場所がずれています。

| | git | プログレスマップ |
|---|---|---|
| 履歴の単位 | 人が書くコミット | check を通った編集すべて（自動） |
| なぜ | 後から書くコミットの説明 | 直した時に付ける理由 ＋ 会話への結び付き |
| 黙って消えた物に気づく | 差分を読む | 消えた行を数え、ALERT で止める |
| 戻す | checkout / revert | 逆向きの差分を一段ずつ検算して当てる |
| 枝分かれ・合流 | ある | **わざと作らない**。一人と AI には手続きが増えるだけ |

引いた線: 枝分かれと合流を作り始めたら、それは git の作り直し。そこで止めます。

## 測った数字

- 51ファイルのウェブアプリの最初の作り直し **1.44秒**、変化なしの2回目 **0.39秒**（2026-10-04）
- 話題を開く **0.36秒**、ファイル1つの位置 **0.08秒**
- 戻しの試験: 改行の CRLF と LF が混ざり、末尾の改行が無い4つの版を、**1バイトも違わず**元に戻せた。差分を壊すと丸ごとの写しに飛んで戻り、写しが無いと切れた段を言って止まった
- 今の利用: 話題 **2**、物 **6,258**、台帳 **7,548** 行（2026-11-07）

表計算のファイルが入ったフォルダを整理して約2,300件をまとめて動かした時は、消えて新しく出たのではなく「大きさ・更新時刻・名前」が同じなら移動とみなし、足跡を新しい場所に引き継ぐようにしました。
